# 本番反映を除く最適化・最終検証

対象: hachi / 2026-09-14 / ローカル作業ツリー

共通の重複取得・先読み・キャッシュ処理を最適化し、今回の追加検証で見つかった承認後のキャッシュ更新漏れも修正しました。ローカル検証は下記の範囲で成功しています。本番へのデプロイ、Git push、本番DBへのインデックス適用は行っていません。

## 追加修正

承認・却下・差戻し・再申請・取消などが成功した際に、会社内のサーバーキャッシュを無効化する処理を追加しました。承認詳細画面では、契約・見積と関連工事、ダッシュボードの React Query キャッシュも更新対象にしました。承認画面だけ更新され、以前開いた契約・見積の表示が残るケースを防ぎます。

認証・プロフィールの同時取得の共有、保存前に開始した読み込みが古いキャッシュを復活させる競合の防止、会社・ユーザー別のキー、設定のタブ別読み込み、メニューの先読み抑制、独立したDB取得の並列化も維持しています。

## 隔離DBで行った確認

PGliteのインメモリPostgreSQLを使用し、2社・1,000ユーザー、承認ステップ・社内メッセージ・発注を各10万件生成しました。実在の業務データは複製していません。

リポジトリの初期スキーマ、RLSポリシー、会社更新ポリシー、社内メッセージDDLを使用しています。Supabase固有の認証スキーマはローカルの代替を用意し、UUID拡張はPostgreSQLの標準関数で代用しました。全マイグレーションを再現したSupabase環境ではなく、対象処理用の検証DBです。

- 追加インデックスSQLを2回適用して成功。
- `authenticated` ロールとRLSを有効にして実行計画を取得。4種類すべてで対象インデックスが採用され、結果が変更前と一致。
- 別会社のデータが見えず、別会社への更新が0件になることを確認。
- 実装済みの `updateCompany`・`updateProfile` をローカルDBアダプター経由で実行し、保存後の再取得とキャッシュ更新を確認。社員による会社編集は拒否。
- 実装済みの承認処理で、順番違い・承認者違い・別テナント・重複承認を拒否。2段階承認の完了と、関連契約の `preparing` → `contracted` への変更を確認。
- 先に別ユーザーでキャッシュした契約が、承認後の読み込みで新しい状態になることを確認。
- 承認後の未処理件数、既読更新後の未読件数が即時に変わることを確認。

通知・Webhook・帳票アーカイブはテスト内で置き換えています。外部への通知・送信は行っておらず、これらの連携自体は今回の検証対象外です。React・認証・Supabaseの通信部分もテスト用アダプターのため、ブラウザーからServer Actionを呼ぶ完全なE2Eテストとは区別してください。

## 反映状況と限界

本番と同じSupabaseへのローカル接続は復旧済みです。本番コード・本番DBの構造・業務データへの保存操作は変更していません。インデックスはローカル検証DBにのみ適用しています。

本番への反映時には、実テーブルの規模、既存インデックス、実行計画、DDL実行中のロックを確認したうえで適用してください。大きいテーブルでは、トランザクション外での `CREATE INDEX CONCURRENTLY` による個別実行を検討する必要があります。この作業は今回の「本番反映以外」の範囲から除外しています。

サーバーキャッシュはサーバーインスタンス内の短いTTLキャッシュです。他インスタンスへの即時無効化を提供する分散キャッシュではありません。全画面の全操作、複数ブラウザーでの同時更新、外部連携、本番配信での表示速度は今回の成功判定に含みません。

開発サーバーとビルドを並行使用した時間帯に、サイドメニューの生成IDに関するhydration警告を1回記録しました。ビルド完了後に同じ工事一覧を再読み込みし、22件の表示と新規コンソールエラー0件を確認しました。原因の断定や、全条件で再発しないという保証はしていません。検証途中の接続許可前には認証通信の失敗もあり、許可後のHTTP検証は全件成功しています。

既存のmiddleware規約の非推奨警告は残ります。また、PDF関連も含む変更ファイル全体のESLintでは、以前からある契約詳細のeffect内setStateエラー2件が残ることを前回確認しています。今回の追加承認修正のlintはエラー0件です。

## 再実行

リポジトリのルートから実行できます。DB検証は `.env.local` を読まず、外部DBに接続しません。

```sh
npm run qa:performance --workspace web
npm run qa:performance-db --workspace web -- /absolute/path/report.json
npm run qa:pdf-builder --workspace web
npm run build --workspace web
```

HTTPルート確認はローカルサーバーを起動し、`QA_EMAIL` と `QA_PASSWORD` を環境変数で渡して `npm run qa:read-only-routes --workspace web -- /absolute/path/report.json` を実行します。接続先URLはループバックに限定し、サービスロールキーは使用しません。

記録: `performance-local-db-verification.json`、`performance-route-smoke.json`、`performance-live-read-measurements.json`、`performance-navigation-measurements.json`。

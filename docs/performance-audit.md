# 読み込み・画面遷移の最適化

対象: hachi / ローカル作業ツリー / 2026-09-14

## 現在の状態

Cursorで使用していた接続設定を確認し、ローカルのSupabase接続を復旧済みです。本番と同じSupabaseで読み取り比較を行い、共通取得の通信16回→2回、中央値612ms→136msを確認しています。

承認後のキャッシュ更新漏れも追加修正しました。性能テスト16件、隔離DB検証10項目、HTTPルート確認54件、PDF回帰テスト13件、型チェック、最終ビルドが成功しています。最新の範囲と限界は `performance-final-verification.md` を参照してください。本番コードと本番DBのインデックスは未反映です。

## 実施範囲

70 個のページ入口と、共通レイアウト・認証・先読み・React Query・サーバーキャッシュ・データ取得・DB マイグレーションを横断調査しました。特に、設定、顧客・案件、契約・工事、カレンダー、承認、回覧、社内メッセージを確認しています。全ページの全操作を実データで実行したという意味ではありません。

## 変更内容

- **認証とプロフィールの重複取得**: 同時に走るブラウザーの取得処理で、同じ認証確認・プロフィール取得を共有します。完了済みの認証結果は TTL で保持せず、次の取得時には再確認します。サーバー側ではブラウザー用の共有処理を使いません。
- **サーバーキャッシュ**: 同じキーへの同時取得を一本化しました。保存・更新による無効化の後に古い取得が完了しても、その結果がキャッシュを再汚染しないようにしました。会社別キャッシュの共通ラッパーは、デフォルトでユーザーもキーに含めます。
- **アカウント切替**: React Query の取得をキャンセルしてキャッシュを破棄し、古いプロフィールの非同期応答が新しい表示を上書きしないようにしました。
- **メニューの先読み**: グループを開いただけで全リンクのデータを取得する処理を削除しました。PC・スマートフォンの両メニューを対象に、リンクに 120 ms 滞在した場合に先読みし、短い通過時には発行しません。キーボードフォーカスとスマートフォンでのリンクへのタッチではすぐ先読みします。
- **設定画面**: 初期データの取得を会社情報・署名に絞りました。メンバー、マスタ、外部連携は該当タブを開いてから取得します。メンバーは React Query で再利用し、会社保存後は関連キャッシュを無効化します。メンバー取得失敗時の再試行案内も追加しました。
- **契約・勘定科目履歴**: 互いに依存しない取得を並列化しました。取得上限や集計対象を削って高速化する変更は行っていません。
- **承認・回覧**: 表示時に最新取得する承認情報への直前の重複先読みを除去しました。回覧詳細は取得処理が既読登録も行うため、ホバー時のデータ取得を除去しました。画面の先読みは残しています。
- **グローバル検索**: 検索語を変更した後で以前の応答が届いても、古い結果が現在の検索を上書きしないようにしました。

既存の React Query の 2 分キャッシュ、画面ごとのキャッシュ、Next.js のルーターキャッシュ、詳細タブの遅延読込は確認したうえで維持しています。期限を一律に延ばす変更はしていません。
